**ISD Team · 2026.06.10**

## 아키텍처 / 설계

**Q. 왜 벡터 DB(Pinecone, Weaviate) 대신 SQLite를 썼나요?**
> SQLite FTS5의 unicode61 토크나이저가 한국어 키워드 검색을 충분히 잘 처리합니다. DB 스키마에 `embedding TEXT` 컬럼을 이미 예약해뒀기 때문에 Phase 2에서 PostgreSQL + pgvector로 전환하기 쉽습니다. FTS5는 외부 서비스도, API 키도, 추가 비용도 없이 데모 범위를 커버합니다.

---

**Q. OpenAI나 Claude 대신 왜 Groq을 썼나요?**
> Groq은 일일 무료 한도가 넉넉하고 레이턴시가 매우 낮아서 실시간 SSE 스트리밍 데모에 유리합니다. 키워드 추출은 llama-3.1-8b(빠르고 저렴), 답변 생성은 llama-3.3-70b(품질)로 역할을 나눠 토큰을 절약했습니다. 429 Rate Limit 발생 시 자동으로 8B 모델로 fallback해서 서비스가 중단되지 않습니다.

---

**Q. 왜 키워드 추출에 8B 모델, 답변에 70B 모델을 따로 쓰나요?**
> 키워드 추출은 질문에서 단어 2~3개를 뽑는 단순한 작업입니다. 70B 모델을 쓰면 토큰 낭비이고 레이턴시만 늘어납니다. 8B 모델이 200ms 이내에 처리합니다. 70B는 한국어 품질이 중요한 최종 답변 생성에만 투입합니다.

---

**Q. FTS5 AND 검색이 결과를 못 찾으면 어떻게 되나요?**
> 3단계 fallback입니다. ① 추출된 키워드로 AND 검색 → ② 결과 없으면 OR로 재시도 → ③ 그래도 없으면 원문 질문 단어들을 OR로 검색하되, 공지사항(`notice` 타입) 청크를 제외합니다. 공지 청크가 강의 관련 질문에 높은 순위로 올라오는 걸 막기 위해서입니다.

---

**Q. "그거"같은 대명사는 어떻게 처리하나요?**
> 키워드 추출기(8B 모델)에게 이전 3개 user 메시지를 컨텍스트로 넘기면서 "대명사(그거, 이것 등)는 앞 대화의 실제 주제어로 바꿔서 출력해"라고 프롬프트에 명시합니다. 별도 NLU 단계 없이 프롬프트 엔지니어링만으로 해결합니다. 실제로 "그거 관련 강의자료 찾아줘" → "DNN"으로 치환해서 PDF를 정확히 검색합니다.

## 스크래퍼 / e-Class

**Q. e-Class에서 데이터를 어떻게 가져왔나요?**
> 학생이 직접 로그인해서 얻은 JSESSIONID 쿠키를 HTTP 세션에 주입합니다. 브라우저가 과제 페이지를 열 때 호출하는 것과 동일한 AJAX 엔드포인트를 직접 POST로 호출합니다 — `report_list.acl`, `project_list.acl`. 학생이 직접 페이지를 탐색하는 것과 동일한 행위입니다.

---

**Q. HTML 파싱 대신 AJAX 엔드포인트를 직접 왜 호출하나요?**
> e-Class의 과제 목록은 JavaScript로 동적 렌더링됩니다. HTML을 직접 가져오면 테이블이 비어 있습니다. 데이터는 `report_list.acl`이 JSON을 반환한 뒤에야 존재합니다. Chrome DevTools의 Network 탭으로 엔드포인트를 역공학했습니다.

---

**Q. 과제 제출 상태(미제출/완료)는 어떻게 판단하나요?**
> e-Class가 각 행에 `<img alt="미제출">` / `<img alt="제출">` 이미지를 넣습니다. 텍스트보다 `img[alt]`를 먼저 확인합니다. 텍스트 기반 검사를 먼저 하면 "미완료"에 "완료"가 포함되어 있어서 미제출 과제가 completed로 잘못 파싱되는 버그가 있었습니다.

---

**Q. 세션이 만료되면 어떻게 감지하나요?**
> 각 요청 이후 응답 URL이 `login_form.acl` 또는 `main_form.acl`로 리다이렉트되는지 확인합니다. 응답 본문에서 "접속이 종료" 문자열을 검사하지 않습니다 — 그 문자열이 e-Class 모든 페이지의 JS 에러 핸들러에 포함되어 있어서 false positive가 발생했던 경험이 있습니다.

## RAG / 채팅

**Q. LLM이 날짜 계산을 틀리면 어떡하나요?**
> 과제/마감 질문은 LLM에 날짜 계산을 맡기지 않습니다. Smart Router가 '과제', '마감', '언제', '이번주' 같은 키워드를 감지하면 `Learning_Activity`를 직접 쿼리합니다. D-day 태그("오늘 마감", "D-3", "마감 14일 지남")는 Python의 `datetime.date`로 계산해서 텍스트로 프롬프트에 주입합니다. LLM은 읽기만 하면 됩니다.

---

**Q. Hybrid history가 뭔가요?**
> 매 턴마다 최근 4개 메시지(recency)를 무조건 포함하고, 거기에 현재 질문 키워드로 `Chat_Log_fts`를 FTS5 검색해서 관련 과거 메시지 최대 3개를 추가합니다. 두 집합을 합쳐서 `chat_id` 순으로 정렬합니다. 컨텍스트 윈도우를 작게 유지하면서 10턴 전 관련 대화도 꺼낼 수 있습니다.

---

**Q. 공지사항 청크가 강의 관련 검색을 오염시키지 않나요?**
> 마지막 fallback 검색에서 `exclude_notice=True` 플래그로 `file_type = 'notice'` 인 Material을 제외합니다. 공지는 과목 특화 어휘를 많이 포함하기 때문에 vague 쿼리에서 높은 순위로 올라옵니다. 직접 공지사항을 물어볼 때는 정상 검색되고, 강의자료 fallback에서만 제외됩니다.

## 개인정보 / 보안

**Q. 학생 데이터는 안전한가요?**
> 모든 데이터는 로컬 SQLite에만 저장됩니다. 외부로 나가는 건 Groq API로 전달되는 질문 텍스트와 검색된 강의자료 청크뿐입니다. JSESSIONID 쿠키는 SQLite에 저장되지만 Groq이나 다른 외부 서버로는 절대 전송되지 않습니다. Groq API 키는 `.env`에만 있고 git에 커밋되지 않습니다.

## 구현 세부사항

**Q. 왜 upsert 대신 clear → insert를 사용하나요?**
> e-Class 활동에는 안정적인 고유 ID가 없습니다. 같은 과제가 학기마다 약간 다른 제목으로 나올 수 있어 upsert 기준이 불명확합니다. 삭제 후 재삽입하면 로컬 상태가 항상 e-Class와 정확히 일치합니다. 제출 완료된 과제는 다음 동기화 때 자동으로 사라지는데, 이게 맞는 동작입니다.

---

**Q. delta sync는 정확히 어떻게 동작하나요?**
> `POST /sync/delta`는 e-Class 알림 목록(`notification_list.acl`)을 파싱해서 최근에 변경된 과목만 골라 재동기화합니다. 전체 sync 대비 훨씬 빠릅니다. Chrome Alarms API와 연결하면 사용자가 버튼을 누르지 않아도 백그라운드에서 자동으로 최신 상태를 유지할 수 있습니다.

---

**Q. `description` 필드는 언제 채워지나요?**
> 동기화 중에 채워집니다. 활동 목록을 받아온 후, `detail_url`이 있는 항목마다(`<td onclick="pageMove(...)">` 에서 추출) 상세 페이지에 별도 요청을 보내서 과제 본문을 스크래핑합니다. 상세 페이지가 없는 퀴즈 등은 `description = NULL`이 되고, 그 경우에는 제목과 마감일만 표시합니다.

---

**Q. Personal_Log는 지금 어디에 쓰이나요?**
> 현재는 과목 페이지 체류 시간(stay_time)을 DB에 기록만 합니다. UI에서 아직 시각화하지 않았습니다. 향후 과목별 학습 시간 히트맵, 참여도 분석, 자주 보는 자료 기반 추천 등에 활용할 수 있는 기반 데이터입니다.
