# LMS-Aware AI Copilot for Personalized Learning
**HUFS ISD Team · June 2026**

---

## 1. Project Overview

A Chrome Extension that connects to the HUFS e-Class LMS and answers student questions about lecture materials and assignments using a local RAG (Retrieval-Augmented Generation) pipeline. No data leaves the local server — lecture PDFs are chunked and stored in SQLite FTS5, and answers are generated by Groq's Llama 3.3 70B.

---

## 2. System Architecture

**6 layers:**

| Layer | Components |
|---|---|
| Chrome Extension | Sidebar UI (panel.html), Cookie Interceptor, Personal_Log tracking |
| FastAPI Backend | /sync, /sync/delta, /chat, /chat/stream (SSE), /feedback, /log, /courses |
| e-Class Scraper | Cookie injection, AJAX POST endpoints (report_list.acl, project_list.acl) |
| Ingest Pipeline | chunker.py — PDF/PPTX → page-level chunks → SQLite FTS5 |
| SQLite Database | 9 tables + 2 FTS5 virtual tables (Doc_Chunk_fts, Chat_Log_fts) |
| RAG Engine | Smart router → FTS5 search → Groq llama-3.3-70b (SSE streaming) |

---

## 3. Data Model (ERD Summary)

- **User** — lms_id, enc_session_cookie, last_sync_at
- **Course / Enrollment** — KJKEY-based course mapping
- **Material / Doc_Chunk** — PDF/PPTX chunks with page_ref, MD5 dedup
- **Learning_Activity** — title, due_date, status (synced via AJAX)
- **Personal_Log** — stay_time per course page (visibilitychange)
- **Chat_Session / Chat_Log** — role, content, keywords, sources (JSON), feedback_score
- **Doc_Chunk_fts / Chat_Log_fts** — FTS5 virtual tables for keyword search

## 4. Key Features Implemented

### 4.1 Automatic LMS Sync
- JSESSIONID captured automatically from Chrome cookies
- Scrapes all enrolled courses: lecture materials (PDF/PPTX) + activities
- Assignment/project data fetched via AJAX POST endpoints (not page HTML)
- `clear_activities` before each sync — submitted assignments disappear automatically
- Incremental delta sync (`POST /sync/delta`) for notification-triggered updates

### 4.2 Smart RAG Pipeline
- **Smart Router**: ACTIVITY_KEYWORDS → Learning_Activity query; MATERIAL_KEYWORDS → FTS5 Doc_Chunk search
- **Keyword Extraction**: llama-3.1-8b-instant (saves tokens vs 70B)
- **Hybrid History**: last 4 turns always + FTS-relevant older messages (up to 3)
- **D-day Tags**: computed in Python before prompt injection — eliminates LLM date math errors
- **Groq Fallback**: llama-3.3-70b primary → llama-3.1-8b on 429 rate limit

### 4.3 SSE Streaming Responses
- `POST /chat/stream` returns `text/event-stream`
- Extension panel reads `ReadableStream` via direct fetch (bypasses background.js)
- Text renders token-by-token in real time; sources + feedback appended on `done` event

### 4.4 Session Continuity
- `session_id` passed back from extension on every turn
- Server validates session ownership before reuse
- Multi-turn context maintained across page navigations

### 4.5 Personal_Log
- `visibilitychange` + `beforeunload` events measure stay_time per course page
- Sent to `POST /log` on page exit; stored in Personal_Log table
- Enables future learning analytics (time-on-task per course)

### 4.6 Feedback Loop
- 👍/👎 buttons on every assistant message
- `POST /chat/{id}/feedback?score=±1` → Chat_Log.feedback_score
- Accumulated data usable for RLHF-style fine-tuning

## 7. Challenges & Solutions

| Challenge | Solution |
|---|---|
| e-Class assignment data in AJAX, not HTML | Reverse-engineered AJAX endpoints (report_list.acl, project_list.acl) via page source analysis |
| Duplicate activities on re-sync | `clear_activities()` deletes all before re-insert; submitted ones disappear naturally |
| LLM wrong about "이번 주" dates | D-day tags computed in Python, embedded in prompt — LLM only reads pre-calculated values |
| Groq 429 rate limit | Fallback from 70B to 8B model; keyword extraction permanently on 8B |
| Chat history always empty (session bug) | Fixed: session_id returned to extension, re-sent on next turn, server validates & reuses |

## 9. How to Run

```bash
# 1. Install dependencies
pip install fastapi uvicorn groq pdfplumber python-pptx requests beautifulsoup4 python-dotenv

# 2. Set env
echo "GROQ_API_KEY=your_key" > .env

# 3. Init DB
python -c "from db.db import init_schema; init_schema()"

# 4. Start server
python -m uvicorn app.main:app --port 8001

# 5. Load extension
# chrome://extensions → Load unpacked → select /extension folder
# Navigate to eclass.hufs.ac.kr → enter student ID → click Sync
```
