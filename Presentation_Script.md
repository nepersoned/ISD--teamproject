# Presentation Script — LMS AI Copilot
**5 minutes English · ISD Team · June 10, 2026**

---

## SLIDE 1 — Title (20초)

> "Hi everyone. We built an **LMS-Aware AI Copilot** — a Chrome Extension that connects directly to HUFS e-Class and answers questions about your lectures and assignments using a local AI pipeline.
>
> The core idea is simple: students shouldn't have to dig through PDFs or the LMS portal just to find out when their homework is due or what was covered in a lecture. Our copilot does that automatically."

---

## SLIDE 2 — ERD (50초)

> "Let me start with the data model.
>
> At the center is **Doc_Chunk** — every PDF and PPTX from e-Class gets split into page-level chunks and indexed with SQLite FTS5 for keyword search.
>
> **Learning_Activity** stores assignments, team projects, and quizzes — synced directly from e-Class's AJAX endpoints, not the HTML page.
>
> **Personal_Log** records how long a student stays on each course page — useful for learning analytics.
>
> And **Chat_Log** stores every conversation with the keywords used, the source chunks referenced, and a feedback score — so the system can improve over time.
>
> Everything lives in a local SQLite database, so no student data goes to any external server."

---

## SLIDE 3 — System Architecture (70초)

> "The system has six layers.
>
> The **Chrome Extension** sits on top. It auto-captures the JSESSIONID cookie — no manual login needed. The sidebar appears on every e-Class page.
>
> The **FastAPI backend** exposes nine endpoints. The key ones are `/sync` for full sync, `/sync/delta` for notification-based incremental sync, and `/chat/stream` which we'll see in the demo.
>
> The **scraper** authenticates via cookie injection and fetches lecture materials through AJAX endpoints. We had to reverse-engineer these because e-Class loads assignment data dynamically — the HTML page itself has zero rows.
>
> Lecture PDFs and PPTX files go through the **ingest pipeline** — text extraction, page-level chunking, MD5 dedup, and FTS5 indexing.
>
> For the **RAG engine**: when a question comes in, a smart router decides the path. Assignment questions go straight to Learning_Activity — no LLM involved. Material questions go through keyword extraction with a small 8B model, then FTS5 search, then prompt assembly.
>
> The final answer is generated by **Groq's llama-3.3-70b** with real-time SSE streaming. If we hit the daily rate limit, it falls back to the 8B model automatically."

---

## SLIDE 4 — Sequence Diagram (50초)

> "Two main flows.
>
> **Sync**: the user clicks sync, the extension sends the cookie to our API, the scraper authenticates, fetches materials and activities course by course, chunks everything, and writes to SQLite. Before inserting activities, we call `clear_activities` — so if you already submitted an assignment, it just disappears from the list on next sync.
>
> **Chat**: the question hits our smart router. If it's about deadlines or assignments, we query Learning_Activity and compute D-day tags in Python — we don't trust the LLM to do date math. If it's about lecture content, we run FTS5 search, build the prompt, and stream the response back token by token via Server-Sent Events."

## Q&A 예상 질문 & 답변

*(15분, Korean/English 혼용)*

---

**Q. How did you get data from e-Class?**
> "We inject the JSESSIONID cookie into our HTTP session and call e-Class's internal AJAX endpoints directly — the same ones the browser calls when you open the assignment page. For example, `report_list.acl` and `project_list.acl` via POST request."

---

**Q. Why SQLite instead of a proper vector database?**
> "SQLite FTS5 with the unicode61 tokenizer handles Korean keyword search well enough for this use case. The schema already has an `embedding TEXT` column reserved for a Phase 2 migration to pgvector, but FTS5 covers the demo scope without the infrastructure overhead."

---

**Q. What's your role in the project?**
*(각자 준비 — 예시)*
> "I was responsible for the RAG pipeline — the smart router, keyword extraction, prompt building, and the streaming endpoint. I also debugged the e-Class scraper when we discovered the assignment pages load via AJAX."

---

**Q. 개인정보는 어떻게 처리했나요?**
> "모든 데이터는 로컬 SQLite에만 저장됩니다. 세션 쿠키는 DB에 저장되지만 외부 서버로 전송되지 않고, Groq API에는 강의 내용 텍스트만 전달됩니다."

---

**Q. delta sync는 정확히 어떻게 동작하나요?**
> "e-Class의 알림 목록 페이지(`notification_list.acl`)를 폴링해서 어느 과목에 변경이 있었는지 파싱하고, 해당 과목만 재동기화합니다. 전체 sync 대비 훨씬 빠릅니다. Chrome Alarms API와 연결하면 완전 자동화도 가능합니다."

---

**Q. Groq 말고 다른 LLM도 고려했나요?**
> "처음에는 Claude API로 설계했는데, 토큰 비용 때문에 Groq으로 전환했습니다. Groq은 일일 무료 한도가 있고 속도가 빠릅니다. 키워드 추출은 8B 모델로, 답변 생성은 70B 모델로 역할을 나눠서 토큰을 절약했습니다."

---

**Q. Personal_Log는 어떻게 쓰이나요?**
> "현재는 체류 시간을 DB에 저장만 합니다. 향후 과목별 학습 시간 히트맵이나 참여도 분석에 활용할 수 있는 기반 데이터입니다."
